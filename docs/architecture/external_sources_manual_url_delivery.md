# External Sources Phase 9 — manual URL routing

`CanonicalManualSourceService` in `backend/app/pipeline/ingestion/external/application/manual_source_service.py` is the framework-independent operation boundary that a future Phase 11 authenticated transport adapter may call. Dashboard code must not invoke collectors directly.

The service uses `ManualURLPolicy`, `ManualURLRouter`, and `SSRFProtectedHttpClient` under the canonical `manual_source/` package. It rejects credentials and non-HTTP(S) schemes, resolves public hosts before every connection and redirect, rejects every non-public address class, strips cookies and authorization headers, performs GET-only bounded streaming, and never permits onion URLs through the public client. Approved onion URLs require both the local Phase 8 policy callback and the configured `dark_web` adapter.

Routing is registry-aware. The local composition passes definitions loaded by the existing `config/sources.json` registry loader into `ManualURLRouter`. Routing precedence is approved onion, CVE/NVD/MITRE, GitHub advisory/public GitHub, configured or structurally detected RSS/Atom and CERT feeds, configured Telegram, configured Reddit, other exact registered source URLs, then generic web. Matches require canonical host and normalized path boundaries rather than loose substring checks. `URLRoute` records the explicit route kind and matched `source_id` when one is available. Response content-type detection can still identify a feed whose URL has no feed-shaped path.

`manual_source/adapters.py` provides thin dependency-injected translations to the canonical Phase 3, Phase 4, Phase 5, Phase 7, and Phase 8 connectors. Registered URLs execute only their matched `source_id`. CVE, NVD, MITRE, and GitHub advisory identifiers use bounded single-identifier connector operations and do not advance global synchronization windows. Approved onion URLs use the existing Tor client and a single allowed-URL operation, without listing expansion. Public GitHub URLs and specific CERT detail URLs that existing connectors cannot safely bound return an explicit `ignored` result. Missing credentials, unavailable Tor, disabled sources, and unconfigured structured URLs also fail closed and never fall back to `WebCrawler`.

Accepted, review, and rejected connector outputs retain their original canonical items and dispositions when crossing the Manual Source boundary. The existing Manual Source state/sink and Phase 10 handoff then persist and deduplicate them; adapters contain no fetching, preprocessing, privacy, classification, or storage implementation.

Generic articles reuse `WebCrawler`, preprocessing, privacy, classification, `ExternalCTIItem`, and atomic `JsonStateManager` storage. Generic listing candidates are canonicalized and deduplicated before ranking. Ranking favors main/article/card/heading and repeated-content context plus paths related to the listing path; navigation, header, footer, forms, cookie/utility containers, contact/auth/legal/tag/pagination paths, and product-category landing pages are excluded or penalized. The configured limit is applied only after ranking. Listings remain restricted to the exact host, bounded to at most 20 links, and followed once. State retains the listing hash, sorted-link-set hash, known children, disappeared-child timestamps, independent child state, conditional headers, and per-stage hashes/status/version/timestamps. A preprocessing, privacy, or model fingerprint change suppresses conditional short-circuiting and reruns downstream processing.

The latest ranked child set is the active snapshot for a listing. A child absent from a later snapshot is removed from the active Manual checkpoint and retained in the retirement ledger with `reason=no_longer_discovered`, `retired_at`, and its original record and run provenance. Active children receive a separate `last_seen_at`; their original `collected_at` is preserved. Phase 10 export membership is rebuilt from active accepted checkpoints, so historical processed files and retired records remain auditable but cannot re-enter a future dataset. Before model inference, utility paths and clearly identified navigation, contact, support, authentication, legal, product-category, and marketing pages are rejected; ambiguous content below the minimum useful length is routed to review.

Compatibility reconciliation version `1.0` also compares each current listing snapshot with accepted Manual checkpoints having the same canonical `parent_listing`. This retires stale children that older code had already removed from `known_sub_links`. Legacy child checkpoints without lifecycle metadata are exportable only while present in that parent snapshot; standalone Manual checkpoints remain active. Missing origin provenance is backfilled from the earliest schema- and SHA-validated export containing the stable `record_id`, and later exports never replace that run ID. The checkpoint migration marker stores the reconciliation version and per-parent snapshot hash so repeated runs preserve the original retirement event.

Phase 9 tests use sanitized fixtures and mocks only. They perform no public network, live API, Tor, or onion request.
